# SpaceClaim-Script

`idealize.py` — скрипт для SpaceClaim (IronPython 2.7, API V251), который превращает
твердотельную модель корпусных конструкций в расчётную модель для ANSYS:
листы → поверхности с толщиной, полособульбы → балки, кницы → поверхности.

Сейчас работают этап 1 (листы) и этап 2 (полособульбы → балки). Этапы книц и закрытия
зазоров — заготовки.

## Требования к входной геометрии

Скрипт классифицирует и обрабатывает каждое тело отдельно, по его габаритам и плоским
граням. От того, как подготовлена модель, зависит результат.

### 1. Дробить модель на компоненты как можно мельче

- Одна связь — одно тело: каждый лист, каждый профиль, каждая кница отдельно.
- Не объединять всё в одно тело (Combine / Merge). Тип тела определяется по соотношению
  его габаритов: лист — это тело, у которого один размер минимум в 10 раз меньше двух
  других. Склеенная из нескольких листов секция под это правило не попадает и
  как лист не распознаётся.
- Срединная поверхность строится из расчёта «одно тело → одна поверхность». Если из
  тела получается несколько поверхностей, скрипт останавливается.

### 2. Избегать сильно криволинейных поверхностей

- Габариты берутся по осям мировой системы координат, толщина — по двум самым большим
  плоским граням. На сильно гнутом листе габарит по толщине завышается, и тело может не
  попасть в листы или получить неверную толщину.
- Тело без плоских граней получает толщину по габариту, с пометкой в отчёте.
- Копирование неплоской грани (режимы `COPY_SIDE = "BOT"` / `"TOP"`) не реализовано.
- Слабо гнутые листы в режиме срединной поверхности (по умолчанию) обрабатываются, но
  результат стоит проверять глазами.

Полособульб — тело с двумя малыми размерами и одним длинным: длина минимум в 8 раз
больше наибольшего размера сечения, сечение не крупнее 450 мм. Он превращается в балку
штатной командой `Beam.ExtractProfile` на копии тела; сечение балки — реальный профиль.
Ось балки проходит через центр тяжести сечения, привязка к обшивке пока не делается.
Габариты считаются по мировым осям, поэтому профиль, идущий под углом к осям, может не
распознаться.

### 3. Не хранить оригинальную геометрию в компонентах

Скрипт рекурсивно обходит все компоненты и берёт из них все тела. Резервная копия
исходной геометрии, лежащая в компоненте той же модели, будет обработана наравне с
основной и даст дубли поверхностей. Оригинал держите в отдельном файле.

### 4. Перед каждым запуском проверять наименование тел

Скрипт пропускает тела, имя которых начинается с `SHEET_`, `BEAM_`, `SMALL_` или `ORIG_`:
так он отличает уже обработанное от нового.

- Исходные тела не должны начинаться с этих префиксов, иначе они будут молча пропущены.
- После обработки исходное тело переименовывается в `ORIG_<имя>` и скрывается, результат
  получает имя вида `SHEET_0012_t8.0_MID` (лист) или `BEAM_0307_L6000` (балка).
- Если результат удалён вручную, а исходник остался с именем `ORIG_...`, он больше не
  обработается — верните ему прежнее имя.
- Номер в имени результата — порядковый номер тела в текущем запуске, поэтому в разных
  запусках номера могут повторяться. Сверяйте имена по отчёту.

## Запуск

1. Открыть модель в SpaceClaim.
2. Вкладка Script → Open script → `idealize.py` → Run.
3. Посмотреть вывод в консоли и отчёт `idealize_report.csv` в папке «Документы».

Если скрипт не стартует, запишите любой скрипт через Record и скопируйте из него первую
строку (`# Python Script, API Version = ...`) в начало `idealize.py`.

## Настройки

Все параметры — в классе `Cfg` в начале файла. Основные:

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `LIMIT` | `5` | Сколько тел обработать на каждом этапе за запуск (`None` — все) |
| `STAGES` | листы и балки | Какие этапы выполнять |
| `BEAM_ON_COPY` | `True` | Извлекать балку из копии тела, сохраняя исходный солид |
| `ONLY_SELECTED` | `False` | Обрабатывать только выделенные тела |
| `DRY_RUN` | `False` | Только классификация и отчёт, без изменений модели |
| `COPY_SIDE` | `"MID"` | Какую поверхность листа брать: `MID`, `BOT`, `TOP` |
| `SHEET_RATIO` | `10.0` | Минимальное отношение габаритов для листа |
| `SHEET_MAX_T` | `60.0` | Максимальная толщина листа, мм |
| `HIDE_ORIGINAL` | `True` | Скрывать исходное тело после обработки |

На новой модели сначала запустите с `DRY_RUN = True` и проверьте по отчёту, что тела
классифицированы верно. Затем обрабатывайте небольшими порциями через `LIMIT`.

## Отчёт

`idealize_report.csv` (разделитель `;`): новое имя, исходное имя, тип, толщина в мм,
сторона выкладки, длина в мм, примечание. В примечании — ошибки и причины пропуска.
